\# REGLAS DEL PROYECTO SEVA (Sistema Educativo de Lengua de Señas) 
## 1\. FUENTE DE VERDAD - La fuente de verdad principal y absoluta de la arquitectura, diseño, base de datos y requerimientos de este proyecto es el archivo: \`docs/MEMORIA\_PROYECTO.md\` - Antes de proponer o ejecutar cualquier cambio, consulta primero ese documento.

## 2\. METODOLOGÍA DE TRABAJO (PASO A PASO Y CONTROL) - PLANIFICA ANTES DE CODIFICAR: Antes de editar o crear cualquier archivo de código, presenta un plan breve de 3 a 5 puntos explicando qué harás y solicita mi aprobación explícita ("¿Procedo?"). - DESARROLLO MODULAR: Trabaja en una sola funcionalidad o archivo a la vez. No avance al siguiente módulo hasta que la etapa actual esté probada y verificada. - PRINCIPIO YAGNI: No agregues librerías externas, frameworks adicionales ni abstracciones complejas sin autorización previa. Mantén el código minimalista, eficiente y limpio.

## 3\. ACCESIBILIDAD Y UI/UX (OBLIGATORIO) - Cumplimiento estricto con WCAG 2 y WAI-ARIA. - Todos los elementos interactivos o botones deben tener una zona táctil mínima de 44x44px (Ley de Fitts). - Conservar los indicadores de enfoque visual claros (\`:focus-visible\` de 3px) para navegación completa por teclado. - Respetar la regla de movimiento reducido \`@media (prefers-reduced-motion: reduce)\` en animaciones. - Usar exclusivamente las variables CSS existentes para mantener la consistencia estética.

## 4\. OPTIMIZACIÓN DE RECURSOS - El entorno de desarrollo corre en un equipo con memoria RAM limitada (8 GB). - Genera código directo, limpio y bien estructurado. Evita comentarios redundantes o duplicación de archivos.
